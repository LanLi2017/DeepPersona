# G1 seed trajectories

This directory contains the small, reviewable subset of existing trajectories
selected for the controlled behavioral-equivalence MVP. It deliberately does
not vendor the multi-gigabyte upstream experiment outputs.

## Layout

- `source/alfworld_tasks.jsonl`: selected ALFWorld task records, including all
  six sampled trajectories per task. Absolute local game paths are converted to
  paths relative to the ALFWorld data root.
- `source/taubench_retail_tasks.jsonl`: selected tau-bench retail task records,
  including all four sampled conversations per task.
- `assets/alfworld/`: the three replay assets (`game.tw-pddl`,
  `initial_state.pddl`, and `traj_data.json`) for every selected ALFWorld task,
  preserving the dataset-relative directory layout.
- `assets/taubench_retail/`: the selected task specifications plus the retail
  policy, database, and split metadata needed to interpret tool calls and
  verifier targets. Voice assets and unrelated benchmark results are excluded.
- `normalized/trajectories.jsonl`: one portable record per trajectory with a
  common envelope and lossless benchmark-specific events.
- `manifests/manifest.json`: source fingerprints, selection rules, selected
  task IDs, counts, and integrity diagnostics.
- `manifests/checksums.sha256`: hashes for every committed snapshot and
normalized data file.

These are **seed trajectories**, not behavioral-equivalence labels. Controlled
variants and pair/triplet labels must be stored separately after replay and
manual review. This prevents source selection from being confused with ground
truth construction.

`tau_success_v2/` is a later candidate-screen artifact built by merging four
existing tau-bench train rollout pools. Its reward-positive trajectories pass a
mechanical execution gate, but the accompanying LLM quality screen shows that
some still violate policy or incompletely resolve the request. It is therefore
not a frozen gold benchmark.

## Selection policy

ALFWorld uses a fixed quota over all six task families. Within each family,
tasks with mixed success/failure outcomes are preferred, followed by tasks with
more unique exact action sequences. Tau-bench excludes malformed/empty episodes
and prefers mixed-outcome tasks with more unique tool-name sequences.

The selection is deterministic. Run `python scripts/prepare_g1_data.py` to
rebuild the snapshots and `python scripts/validate_g1_data.py` to check them.
Use `PYTHONPATH=../icrl ../alfworld-venv/bin/python
scripts/validate_alfworld_replay.py` to execute every copied ALFWorld action
sequence against its copied environment assets.
For the full check, prefer `bash scripts/submit_alfworld_replay.sh`;
it deterministically distributes the 96 trajectories across 16 CPU-array
elements (one task and its six trajectories per element). Each task environment
is initialized once and reset between trajectories.

## Important limitations

- Selection is intentionally information-rich and is not representative of the
  benchmark distribution.
- Exact action/tool diversity is used only for choosing useful seed examples;
  it is not treated as the target semantic metric.
- The tau-bench source contains synthetic customer-service identities and order
  details generated by the benchmark.
- No controlled variant should be labelled behavior-preserving merely because
  reward is unchanged. Environment state/effect and strategy structure must be
  checked separately.
